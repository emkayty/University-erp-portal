# V22 High-Priority Page Acceptance Criteria

The following workflows are the first visual migration targets.

## Dashboard
- Role-aware summary
- No decorative KPI overload
- "Needs attention" is prioritized
- Quick actions are task-oriented
- Important alerts have severity and destination
- Mobile shows the same priorities as desktop

## Admissions
- Applicant identity/status visible immediately
- Application progress obvious
- Missing/invalid items surfaced before general information
- Qualification data is structured, not arbitrary free text
- Review/decision actions are prominent but permission-protected
- Applicant timeline/history is easy to scan

## Student
- Current academic status is immediately visible
- Programme, level, session and semester are clear
- Academic/financial/support information is grouped
- Sensitive information is permission-aware
- Quick actions reflect staff role

## Course registration
- Current semester/session always visible
- Registered credits and limits obvious
- Prerequisite/conflict failures explain the reason
- Successful registration provides a receipt/summary
- Mobile course selection remains usable

## Exams & grading
- Course/semester/assessment context never ambiguous
- Draft vs submitted vs moderated vs published is explicit
- Grade entry minimizes repetitive work
- Bulk upload includes template, validation preview and error recovery
- Published results are visually distinct and protected
- Audit/history is available to authorized users

## Finance
- Amount, invoice, payment state and balance are unambiguous
- Payment action is separated from receipt/history
- Failed/pending payments explain next steps
- Sensitive payment information is minimized
- Reconciliation exceptions are obvious to finance staff

## Cross-cutting
Every page must have:
- loading state
- empty state
- error state
- unauthorized state
- success feedback
- responsive behavior
- keyboard access
- accessible labels
- consistent terminology
